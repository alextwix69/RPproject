## 1. Базовая теория `python-telegram-bot`

`python-telegram-bot`, часто сокращают как **PTB**, — это библиотека для написания Telegram-ботов на Python. В современных версиях она работает в асинхронном стиле: обработчики пишутся через `async def`, а отправка сообщений делается через `await`.

Минимальный бот обычно состоит из таких частей:

```text
project/
  .env
  config.py
  pyproject.toml
  src/
    bot.py
    core/
      config.py
    handlers/
      start.py
    keyboards/
      main_menu.py
    services/
      user_service.py
  tests/
    test_user_service.py
```

Главная идея архитектуры:

```text
Telegram -> Update -> Handler -> Service / Keyboard -> Reply to user
```

- **Update** — входящее событие от Telegram: сообщение, команда, нажатие кнопки.
- **Handler** — обработчик события. Например, обработчик команды `/start`.
- **Service** — обычная Python-логика без Telegram API. Например, список пунктов меню.
- **Keyboard** — функция, которая собирает кнопки.
- **Application** — объект приложения PTB, куда подключаются handlers.

## 2. dezydope: конфигурация, запуск бота, технический каркас

Зона ответственности dezydope: токен, `.env`, `src/bot.py`, подключение handler-ов, запуск polling, зависимости.

---

### 2.1. `Path(".env")`

**Функция / объект**

```python
from pathlib import Path

env_path = Path(".env")
```

**Пример**

```python
# src/core/config.py

from pathlib import Path

env_path = Path(".env")
```

**Описание**

`Path(".env")` создаёт объект пути к файлу `.env` в корне проекта.  
Файл `.env` нужен, чтобы не хранить токен бота прямо в коде.

Пример `.env`:

```env
API_KEY=123456789:telegram_bot_token_here
```

Почему это важно:

- токен нельзя коммитить в Git;
- `.env` легко заменить на другом компьютере;
- вся команда понимает, где искать `API_KEY`.

---

### 2.2. `load_dotenv(dotenv_path=env_path)`

**Функция**

```python
load_dotenv(dotenv_path=env_path)
```

**Пример**

```python
# src/core/config.py

from pathlib import Path
from dotenv import load_dotenv

env_path = Path(".env")
load_dotenv(dotenv_path=env_path)
```

**Описание**

`load_dotenv()` загружает переменные из файла `.env` в окружение Python-процесса.  
После этого можно получить значение через `os.getenv("API_KEY")`.

Важно для новичков: `load_dotenv()` не создаёт токен сам. Он только читает файл `.env`.

---

### 2.3. `os.getenv("API_KEY")`

**Функция**

```python
os.getenv("API_KEY")
```

**Пример**

```python
import os

api_key = os.getenv("API_KEY")
```

**Описание**

`os.getenv()` получает значение переменной окружения.  
Если переменной нет, функция вернёт `None`.

Проблема такого варианта:

```python
api_key = os.getenv("API_KEY")
```

Если ключа нет, ошибка появится позже и будет не очень понятной. Поэтому новичкам удобнее сделать отдельную функцию `get_api_key()`.

---

### 2.4. `get_api_key()`

**Функция**

```python
def get_api_key() -> str:
    ...
```

**Пример**

```python
# src/core/config.py

import os
from pathlib import Path
from dotenv import load_dotenv

env_path = Path(".env")
load_dotenv(dotenv_path=env_path)


def get_api_key() -> str:
    api_key = os.getenv("API_KEY")

    if not api_key:
        raise RuntimeError(
            "API_KEY не найден. Создай файл .env в корне проекта "
            "и добавь строку API_KEY=твой_токен"
        )

    return api_key
```

**Описание**

`get_api_key()` — это аккуратный способ получить токен бота.  
Функция делает три вещи:

1. Берёт `API_KEY` из окружения.
2. Проверяет, что ключ не пустой.
3. Если ключа нет, сразу показывает понятную ошибку.

`raise RuntimeError(...)` нужен, чтобы программа остановилась с объяснением проблемы.

Для новичков этот вариант обычно понятнее, чем просто импортировать `API_KEY`, потому что ошибка становится явной.

### 2.6. `ApplicationBuilder`

**Функция / класс**

```python
ApplicationBuilder()
```

**Пример**

```python
from telegram.ext import ApplicationBuilder

application = ApplicationBuilder().token("TOKEN").build()
```

**Описание**

`ApplicationBuilder` собирает объект приложения Telegram-бота.  
Он работает как “строитель”:

1. `ApplicationBuilder()` — начинаем сборку.
2. `.token(token)` — передаём токен бота.
3. `.build()` — получаем готовое приложение.

Готовое приложение потом умеет:

- принимать сообщения;
- хранить список handlers;
- запускаться через polling;
- отправлять ответы пользователям.

---

### 2.7. `build_application()`

**Функция**

```python
def build_application():
    ...
```

**Пример**

```python
# src/bot.py

from telegram.ext import ApplicationBuilder

from src.core.config import get_api_key
from src.handlers.start import register_start_handlers


def build_application():
    token = get_api_key()

    application = ApplicationBuilder().token(token).build()
    register_start_handlers(application)

    return application
```

**Описание**

`build_application()` — отдельная функция для сборки бота.  
Она полезна, потому что код запуска становится чище.

Внутри неё:

1. Получаем токен.
2. Создаём application.
3. Подключаем handlers.
4. Возвращаем готовое приложение.

Новичкам важно не смешивать всё в одном месте.  
`build_application()` отвечает только за сборку, а не за отдельную логику `/start` или меню.

---

### 2.8. `application.add_handler(...)`

**Функция**

```python
application.add_handler(handler)
```

**Пример**

```python
from telegram.ext import CommandHandler

application.add_handler(CommandHandler("start", start))
```

**Описание**

`add_handler()` добавляет обработчик в приложение.  
Обработчик говорит боту:

> “Когда пользователь отправит такую команду или такое сообщение — вызови эту функцию”.

Например:

```python
CommandHandler("start", start)
```

означает:

> “Когда пользователь отправит `/start`, вызови функцию `start`”.

---

### 2.9. `application.run_polling()`

**Функция**

```python
application.run_polling()
```

**Пример**

```python
application.run_polling()
```

**Описание**

`run_polling()` запускает бота в режиме polling.

Polling — это когда бот сам регулярно спрашивает Telegram:

> “Есть ли новые сообщения?”

Для учебного проекта это самый простой способ запуска.  
Webhook пока не нужен, потому что он сложнее и требует публичного сервера.

---

### 2.10. `main()`

**Функция**

```python
def main() -> None:
    ...
```

**Пример**

```python
# src/bot.py

def main() -> None:
    application = build_application()
    application.run_polling()


if __name__ == "__main__":
    main()
```

**Описание**

`main()` — главная точка входа в программу.  
Когда запускается файл `src/bot.py`, Python дойдёт до блока:

```python
if __name__ == "__main__":
    main()
```

и вызовет функцию `main()`.

Такой стиль удобен, потому что:

- код запуска лежит в одном месте;
- приложение можно импортировать в тестах;
- структура проекта выглядит профессиональнее.

### 2.12. Минимальный итоговый `src/bot.py`

**Функция / файл**

```python
build_application()
main()
```

**Пример**

```python
# src/bot.py

from telegram.ext import ApplicationBuilder

from src.core.config import get_api_key
from src.handlers.start import register_start_handlers


def build_application():
    token = get_api_key()

    application = ApplicationBuilder().token(token).build()
    register_start_handlers(application)

    return application


def main() -> None:
    application = build_application()
    application.run_polling()


if __name__ == "__main__":
    main()
```

**Описание**

Это минимальная точка запуска.  
Она не содержит игровой логики, БД и сложной инфраструктуры.  
Её задача — собрать приложение и запустить бота.

## 3. laurencic: `/start`, приветствие и стартовые тексты

Зона ответственности laurencic: первый пользовательский вход, команда `/start`, приветствие, стартовый тон, подключение меню к ответу.

---

### 3.1. `async def start(update, context)`

**Функция**

```python
async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    ...
```

**Пример**

```python
from telegram import Update
from telegram.ext import ContextTypes


async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text("Добро пожаловать в лобби.")
```

**Описание**

`start()` — обработчик команды `/start`.

Почему `async def`:

- современные версии PTB работают асинхронно;
- отправка сообщения в Telegram — это операция ожидания;
- поэтому внутри используется `await`.

Почему в функции есть `update`:

- через `update` мы узнаём, что прислал пользователь;
- через `update.message` можно ответить на сообщение;
- через `update.effective_user` можно получить данные пользователя.

Почему есть `context`:

- `context` хранит дополнительные данные обработчика;
- через него можно получить аргументы команды;
- позже в нём могут появиться `user_data`, `chat_data`, настройки и другие вещи.

---

### 3.2. `update.message.reply_text(...)`

**Функция**

```python
await update.message.reply_text(text)
```

**Пример**

```python
await update.message.reply_text("Привет! Ты вошёл в главное меню.")
```

**Описание**

`reply_text()` отправляет текстовый ответ в тот же чат.

Важно: перед `reply_text()` нужен `await`, потому что бот отправляет сообщение через сеть.

Плохой вариант:

```python
update.message.reply_text("Привет")
```

Хороший вариант:

```python
await update.message.reply_text("Привет")
```

---

### 3.3. `START_TEXT`

**Функция / константа**

```python
START_TEXT = "..."
```

**Пример**

```python
START_TEXT = (
    "Добро пожаловать в RP-лобби.\n\n"
    "Здесь позже появятся комнаты, роли и участники. "
    "Пока можно открыть лобби, профиль или помощь."
)
```

**Описание**

`START_TEXT` — это стартовый текст бота.  
Лучше хранить его отдельно от логики функции.

Плохо:

```python
async def start(update, context):
    await update.message.reply_text("Очень длинный текст ...")
```

Лучше:

```python
START_TEXT = "Добро пожаловать в RP-лобби."


async def start(update, context):
    await update.message.reply_text(START_TEXT)
```

Так легче заменить текст, когда появится конкретный сценарий role-play.

---

### 3.4. `HELP_TEXT`

**Функция / константа**

```python
HELP_TEXT = "..."
```

```python
HELP_TEXT = (
```

### 3.6. `CommandHandler("start", start)`

**Функция / класс**

```python
CommandHandler("start", start)
```

**Пример**

```python
from telegram.ext import CommandHandler

application.add_handler(CommandHandler("start", start))
```

**Описание**

`CommandHandler` связывает команду Telegram с Python-функцией.

Команда:

```text
/start
```

Функция:

```python
async def start(update, context):
    ...
```

Связка:

```python
CommandHandler("start", start)
```

Важно: в `CommandHandler` пишется `"start"` без слэша.

---

### 3.7. `register_start_handlers(application)`

**Функция**

```python
def register_start_handlers(application) -> None:
    ...
```

**Пример**

```python
# src/handlers/start.py

from telegram import Update
from telegram.ext import CommandHandler, ContextTypes

from src.keyboards.main_menu import build_main_menu

START_TEXT = (
    "Добро пожаловать в RP-лобби.\n\n"
    "Пока доступны базовые разделы: Лобби, Профиль и Помощь."
)


async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text(
        START_TEXT,
        reply_markup=build_main_menu(),
    )


def register_start_handlers(application) -> None:
    application.add_handler(CommandHandler("start", start))
```

**Описание**

`register_start_handlers()` нужна, чтобы `src/bot.py` не знал лишних деталей.

В `src/bot.py` будет только:

```python
register_start_handlers(application)
```

А внутри `start.py` уже хранится информация о том, какой именно handler нужно добавить.

Это помогает разделить ответственность:

- `bot.py` запускает приложение;
- `start.py` отвечает за `/start`;
- `main_menu.py` отвечает за кнопки.

---

### 3.8. Проверка `/start` руками

**Функция / действие**

```text
/start
```

**Пример**

1. Запустить бота.
2. Открыть чат с ботом в Telegram.
3. Отправить `/start`.
4. Проверить, что пришёл текст.
5. Проверить, что появились кнопки.

**Описание**

На этом этапе не нужно проверять всё автоматически.  
Главный критерий готовности для laurencic:

- пользователь отправляет `/start`;
- бот отвечает приветствием;
- приветствие не обещает неготовую механику;
- вместе с текстом появляется главное меню.

## 4. alextwix: главное меню, лобби-навигация и простая проверка

Зона ответственности alextwix: клавиатура главного меню, будущая лобби-навигация, простая сервисная функция и первый тест без Telegram-мока.

---

### 4.1. `ReplyKeyboardMarkup`

**Функция / класс**

```python
ReplyKeyboardMarkup(...)
```

**Пример**

```python
from telegram import ReplyKeyboardMarkup

keyboard = ReplyKeyboardMarkup(
    [["Лобби", "Профиль"], ["Помощь"]],
    resize_keyboard=True,
)
```

**Описание**

`ReplyKeyboardMarkup` создаёт обычную клавиатуру под строкой ввода в Telegram.  
Для новичков это проще, чем inline-кнопки, потому что пользователь нажимает кнопку, а бот получает обычный текст сообщения.

Например, пользователь нажал кнопку:

```text
Помощь
```

Бот получит сообщение с текстом `"Помощь"`.

---

### 4.2. `build_main_menu()`

**Функция**

```python
def build_main_menu() -> ReplyKeyboardMarkup:
    ...
```

**Пример**

```python
# src/keyboards/main_menu.py

from telegram import ReplyKeyboardMarkup

MAIN_MENU_BUTTONS = [
    ["Лобби", "Профиль"],
    ["Помощь"],
]


def build_main_menu() -> ReplyKeyboardMarkup:
    return ReplyKeyboardMarkup(
        MAIN_MENU_BUTTONS,
        resize_keyboard=True,
        input_field_placeholder="Выбери раздел",
    )
```

**Описание**

`build_main_menu()` собирает главное меню.

Почему отдельная функция лучше, чем писать клавиатуру прямо в `/start`:

- меню можно переиспользовать в разных handlers;
- `start.py` остаётся коротким;
- alextwix может работать с меню независимо от laurencic.

Кнопки для текущего roadmap:

- `Лобби`;
- `Профиль`;
- `Помощь`.

Кнопку `Начать сцену` пока не добавляем, потому что механики комнат и сцен ещё нет.

---

### 4.3. `MAIN_MENU_BUTTONS`

**Функция / константа**

```python
MAIN_MENU_BUTTONS = [...]
```

**Пример**

```python
MAIN_MENU_BUTTONS = [
    ["Лобби", "Профиль"],
    ["Помощь"],
]
```

**Описание**

`MAIN_MENU_BUTTONS` — список рядов кнопок.

Структура:

```python
[
    ["Кнопка 1", "Кнопка 2"],
    ["Кнопка 3"],
]
```

означает:

```text
[Кнопка 1] [Кнопка 2]
[Кнопка 3]
```

Так новичкам проще контролировать внешний вид меню.

---

### 4.4. `get_menu_items()`

**Функция**

```python
def get_menu_items() -> list[str]:
    ...
```

**Пример**

```python
# src/services/user_service.py

def get_menu_items() -> list[str]:
    return ["Лобби", "Профиль", "Помощь"]
```

**Описание**

`get_menu_items()` — чистая функция сервиса.  
Она не зависит от Telegram и просто возвращает список пунктов меню.

Чистая функция — это функция, которую легко проверить:

```python
items = get_menu_items()
assert "Помощь" in items
```

Зачем нужен service:

- handler не превращается в склад данных;
- меню и тексты можно тестировать без запуска бота;
- будущую логику профиля или лобби будет проще расширять.

---

### 4.5. `get_help_text()`

**Функция**

```python
def get_help_text() -> str:
    ...
```

**Пример**

```python
# src/services/user_service.py

def get_help_text() -> str:
    return (
        "Помощь:\n"
        "• Лобби — будущий список комнат и участников.\n"
        "• Профиль — будущая карточка участника.\n"
        "• Помощь — краткое описание доступных действий."
    )
```

**Описание**

`get_help_text()` возвращает текст помощи.  
Это тоже чистая функция: её можно проверить без Telegram.

Например:

```python
text = get_help_text()
assert "Лобби" in text
```

Пока help-текст должен быть честным:

- можно говорить “будущий список комнат”;
- не нужно говорить “комнаты уже работают”.

---

### 4.6. `MessageHandler`

**Функция / класс**

```python
MessageHandler(filters.TEXT & ~filters.COMMAND, callback)
```

**Пример**

```python
from telegram.ext import MessageHandler, filters

application.add_handler(
    MessageHandler(filters.TEXT & ~filters.COMMAND, handle_menu_text)
)
```

**Описание**

`MessageHandler` обрабатывает обычные сообщения пользователя.  
Он понадобится, если команда решит реагировать на кнопки меню.

Пояснение фильтра:

```python
filters.TEXT
```

означает “только текстовые сообщения”.

```python
~filters.COMMAND
```

означает “не команды”.

Полный вариант:

```python
filters.TEXT & ~filters.COMMAND
```

означает:

> “Обрабатывай обычный текст, но не трогай `/start` и другие команды”.

Для текущего roadmap это можно подготовить как заготовку, но не обязательно делать полную навигацию.

---

### 4.7. `handle_menu_text(update, context)`

**Функция**

```python
async def handle_menu_text(update, context) -> None:
    ...
```

**Пример**

```python
# src/handlers/menu.py

from telegram import Update
from telegram.ext import ContextTypes

from src.services.user_service import get_help_text


async def handle_menu_text(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    text = update.message.text

    if text == "Помощь":
        await update.message.reply_text(get_help_text())
        return

    if text == "Лобби":
        await update.message.reply_text("Лобби пока готовится.")
        return

    if text == "Профиль":
        await update.message.reply_text("Профиль пока готовится.")
        return

    await update.message.reply_text("Выбери пункт из меню.")
```

**Описание**

`handle_menu_text()` — пример обработки кнопок reply-клавиатуры.

Важно: это не полноценная игровая логика.  
Это только безопасная заготовка:

- `Лобби` не создаёт комнату;
- `Профиль` не требует базы данных;
- `Помощь` показывает текст.

### 4.8. `pytest` и простая проверка сервиса

**Функция / инструмент**

```python
assert
```

**Пример**

```python
# tests/test_user_service.py

from src.services.user_service import get_help_text, get_menu_items


def test_menu_items_not_empty():

    assert items
    assert "Лобби" in items
    assert "Профиль" in items
    assert "Помощь" in items

    assert text
    assert "Лобби" in text
```

**Описание**

Первый тест лучше писать не на Telegram API, а на обычную функцию.

Почему не нужно мокать Telegram на этом этапе:

- это сложнее;

- roadmap просит минимальный рабочий каркас, а не полноценный тестовый стенд.

## 5. Как части соединяются вместе

Итоговый поток работы после соединения файлов:

```text
1. Пользователь пишет /start
2. Telegram отправляет Update боту
3. Application находит CommandHandler("start", start)
4. Вызывается async-функция start()
5. start() отправляет START_TEXT
6. start() прикрепляет build_main_menu()
7. Пользователь видит кнопки Лобби / Профиль / Помощь
```

Минимальная связка файлов:

```text
src/core/config.py
  get_api_key()

src/bot.py
  build_application()
  main()

src/handlers/start.py
  start()
  register_start_handlers()

src/keyboards/main_menu.py
  build_main_menu()

src/services/user_service.py
  get_menu_items()
  get_help_text()

tests/test_user_service.py
  test_menu_items_not_empty()
  test_help_text_not_empty()
```

## 6. Частые ошибки новичков

### Ошибка 1. Указывать `/start` внутри `CommandHandler`

Плохо:

```python
CommandHandler("/start", start)
```

Хорошо:

```python
CommandHandler("start", start)
```

---

### Ошибка 2. Забыть `await`

Плохо:

```python
update.message.reply_text("Привет")
```

Хорошо:

```python
await update.message.reply_text("Привет")
```

---

### Ошибка 3. Хранить токен прямо в коде

Плохо:

```python
TOKEN = "123456789:secret"
```

Хорошо:

```python
TOKEN = get_api_key()
```

---

### Ошибка 4. Делать слишком много сразу

Плохо:

```text
Сразу добавить БД, Redis, FSM, админку, комнаты и роли.
```

Хорошо:

```text
Сначала сделать /start, меню, сервис и запуск.
```

---

### Ошибка 5. Путать handler и service

Плохо:

```python
async def start(update, context):
    menu_items = ["Лобби", "Профиль", "Помощь"]
    help_text = "..."
    keyboard = ...
    await ...
```

Хорошо:

```python
# handler принимает событие и отправляет ответ
# service хранит чистую бизнес-логику
# keyboard строит кнопки
```

## 9. Короткий словарь

**Bot token / API_KEY** — секретный токен от BotFather, по которому Telegram понимает, каким ботом управляет программа.

**Application** — главный объект PTB-приложения, внутри которого регистрируются handlers.

**Handler** — обработчик события. Например, `CommandHandler("start", start)`.

**Update** — входящее событие от Telegram.

**Context** — объект с дополнительными данными обработчика.

**Polling** — простой режим запуска, когда бот сам спрашивает Telegram о новых сообщениях.

**Reply keyboard** — клавиатура с обычными кнопками под строкой ввода.

**Service** — файл с обычной Python-логикой без Telegram API.

**Чистая функция** — функция, которую можно проверить без запуска Telegram-бота.

## 10. Минимальный учебный пример всех частей

### `src/core/config.py`

```python
import os
from pathlib import Path

from dotenv import load_dotenv

env_path = Path(".env")
load_dotenv(dotenv_path=env_path)


def get_api_key() -> str:
    api_key = os.getenv("API_KEY")

    if not api_key:
        raise RuntimeError(
            "API_KEY не найден. Добавь API_KEY=твой_токен в .env"
        )

    return api_key
```

```python
MAIN_MENU_BUTTONS = [

    ["Помощь"],

def build_main_menu() -> ReplyKeyboardMarkup:
    return ReplyKeyboardMarkup(

        resize_keyboard=True,
        input_field_placeholder="Выбери раздел",
    )
```

### `src/services/user_service.py`


### `src/handlers/start.py`

```python
from telegram import Update
from telegram.ext import CommandHandler, ContextTypes

from src.keyboards.main_menu import build_main_menu

START_TEXT = (
    "Добро пожаловать в RP-лобби.\n\n"
    "Пока доступны базовые разделы: Лобби, Профиль и Помощь."
)


async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text(
        START_TEXT,
        reply_markup=build_main_menu(),
    )


def register_start_handlers(application) -> None:
    application.add_handler(CommandHandler("start", start))
```

### `src/bot.py`

```python
from telegram.ext import ApplicationBuilder

from src.core.config import get_api_key
from src.handlers.start import register_start_handlers


def build_application():
    token = get_api_key()

    application = ApplicationBuilder().token(token).build()
    register_start_handlers(application)

    return application


def main() -> None:
    application = build_application()
    application.run_polling()


if __name__ == "__main__":
    main()
```

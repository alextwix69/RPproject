# Roadmap на 3 рабочих часа

Дата: 23.05  
Проект: role-play Telegram-бот на `python-telegram-bot`  
Команда: dezydope, laurencic, alextwix

## Общая цель

Подготовить минимальный и понятный новичкам каркас role-play Telegram-бота:

- согласованный способ получения `API_KEY`;
- рабочая точка запуска бота;
- базовая команда `/start`;
- простая структура `handlers`, `keyboards`, `services`;
- главное меню как основа будущего онлайн-лобби.

Важно: за эти 3 часа не нужно делать полноценную игру, базу данных, админку или сложные RP-механики. Главная задача - получить аккуратную основу, на которой команда сможет безопасно продолжать разработку.

## Распределение зон

- dezydope - конфигурация, запуск бота, технический каркас.
- laurencic - пользовательский вход, `/start`, приветствие и стартовые тексты.
- alextwix - главное меню, заготовка лобби-навигации и простая тестовая проверка.

## dezydope: конфигурация и запуск бота

### Задача 1. Обсудить способ получения API_KEY

Описание: перед реализацией согласовать с командой, как именно проект будет получать токен бота: через функцию `get_api_key()` или через импорт значения из `config.py`.

Подзадачи:

- Сравнить два варианта: `get_api_key()` и `from config import API_KEY`.
- Обсудить, какой вариант будет понятнее для команды новичков.
- Зафиксировать решение в коротком комментарии или README-заметке, если останется время.
- В `src/core/config.py` оставить `env_path = Path(".env")`.
- Оставить загрузку `.env` через `load_dotenv(dotenv_path=env_path)`.
- Если выбран вариант с функцией, сделать `get_api_key()` и понятную ошибку при отсутствии ключа.
- Если выбран вариант с импортом, оставить `API_KEY` в конфиге и не размазывать чтение env по проекту.
- В корневом `config.py` временно оставить совместимый экспорт выбранного способа и `env_path`.

Критерий готовности:

- Команда выбрала один способ получения `API_KEY`.
- `env_path` не потерян.
- Старый корневой `config.py` не ломает возможные старые импорты.

### Задача 2. Сделать минимальную точку запуска бота

Описание: подготовить `src/bot.py` под библиотеку `python-telegram-bot`.

Подзадачи:

- Импортировать `ApplicationBuilder` из `telegram.ext`.
- Получать токен способом, который команда выбрала в задаче обсуждения.
- Создать функцию `build_application()`.
- Создать функцию `main()`.
- В `main()` собрать приложение и запустить polling.
- Не добавлять сложную инфраструктуру, БД, Redis и middleware.

Критерий готовности:

- В `src/bot.py` есть понятная точка входа.
- Бот можно будет запускать после установки зависимостей.

### Задача 3. Подготовить зависимости проекта

Описание: зафиксировать минимальную зависимость от `python-telegram-bot`.

Подзадачи:

- Добавить в `pyproject.toml` минимальное описание проекта, если файл пустой.
- Указать зависимость `python-telegram-bot`.
- Не добавлять лишние библиотеки без необходимости.

Критерий готовности:

- Новому участнику понятно, какая библиотека нужна для запуска бота.

## laurencic: /start и стартовые тексты

### Задача 1. Реализовать обработчик /start

Описание: сделать первый пользовательский вход в бота.

Подзадачи:

- В `src/handlers/start.py` создать async-функцию обработчика `/start`.
- Ответить пользователю коротким приветствием в стиле role-play проекта.
- Не завязываться пока на базу данных и регистрацию.
- Экспортировать handler или функцию подключения обработчика так, чтобы dezydope мог подключить её в `src/bot.py`.

Критерий готовности:

- Пользователь отправляет `/start` и получает приветственное сообщение.

### Задача 2. Подключить главное меню к /start

Описание: использовать готовую функцию главного меню после того, как alextwix подготовит клавиатуру.

Подзадачи:

- Договориться с alextwix о названии функции меню.
- В обработчике `/start` отправлять приветствие вместе с главным меню.
- Не добавлять обработку всех кнопок сразу.
- Не запускать role-play сцену из `/start`.

Критерий готовности:

- `/start` показывает пользователю меню.
- Приветствие не обещает механику комнат, которая ещё не реализована.

### Задача 3. Описать стартовый тон бота

Описание: зафиксировать короткие тексты, чтобы команда дальше писала в одном стиле.

Подзадачи:

- Добавить приветственный текст в `start.py` или отдельную константу.
- Сделать текст нейтральным и расширяемым: без сложного лора на старте.
- Подготовить короткий текст для кнопки `Помощь`.

Критерий готовности:

- У бота есть единый стартовый тон.
- Тексты легко заменить, когда появится конкретный сценарий RP.

## alextwix: главное меню и заготовка лобби-навигации

### Задача 1. Создать главное меню

Описание: подготовить главное меню как первый пользовательский экран после `/start`. Бот работает как онлайн-лобби с участниками role-play, поэтому пока не нужно начинать сцену: сначала нужны комнаты, участники, роли и состояния.

Подзадачи:

- В `src/keyboards/main_menu.py` создать функцию сборки главного меню.
- Использовать один простой тип клавиатуры: reply-кнопки или inline-кнопки.
- Добавить пункты под будущую лобби-логику: `Лобби`, `Профиль`, `Помощь`.
- Не добавлять кнопку `Начать сцену`, пока нет механики комнат.
- Передать laurencic название функции и формат подключения меню.

Критерий готовности:

- У проекта есть главное меню, которое можно показать после `/start`.
- Названия кнопок не обещают готовую игровую комнату или сцену.

### Задача 2. Подготовить заготовку сервиса для меню

Описание: показать команде простое разделение между handler и логикой отображения меню без преждевременной реализации комнат.

Подзадачи:

- В `src/services/user_service.py` создать простую функцию, которая возвращает список доступных пунктов меню или текст помощи.
- Не хранить в сервисе полноценную механику комнат.
- Handler должен только принимать событие и отправлять ответ.

Критерий готовности:

- Handler не превращается в склад текстов и списков кнопок.
- Команда видит, зачем нужны `services`.

### Задача 3. Добавить простую тестовую проверку

Описание: сделать первый маленький тест без сложного Telegram-мока.

Подзадачи:

- В `tests/test_start.py` или `tests/test_registration.py` проверить чистую функцию сервиса.
- Например, проверить, что список пунктов меню или текст помощи не пустой.
- Не пытаться за 3 часа полноценно тестировать Telegram API.

Критерий готовности:

- Есть хотя бы один простой тест на чистую функцию.
- Тест показывает новичкам, как проверять код без запуска Telegram.

## Ожидаемый итог

К концу 3 часов в проекте должен быть минимальный рабочий вертикальный срез:

1. Команда выбрала и зафиксировала способ получения `API_KEY`.
2. `src/bot.py` собирает и запускает приложение `python-telegram-bot`.
3. `/start` отвечает пользователю.
4. Пользователь видит главное меню.
5. Главное меню готовит основу для будущего онлайн-лобби.
6. Есть хотя бы одна простая тестовая проверка сервисной функции.

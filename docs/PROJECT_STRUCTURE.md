# Структура проекта Telegram-бота

Документ описывает, за что отвечает каждая папка и файл в проекте. Многие файлы сейчас пустые и являются архитектурными заготовками; ниже указана их системная роль.

## Корень проекта

`.git/` - служебная папка Git; хранит историю коммитов, ветки, индекс и внутренние данные репозитория. В код приложения не входит.

`alembic/` - папка миграций базы данных. Нужна, чтобы контролируемо менять структуру БД: таблицы, индексы, связи, поля.

`docker/` - файлы для сборки и запуска проекта внутри Docker-контейнера.

`logs/` - место для runtime-логов приложения. В репозиторий сохраняется только `.gitkeep`, реальные логи игнорируются.

`scripts/` - отдельные служебные скрипты для ручных или одноразовых операций: сидинг базы, настройка webhook и похожие задачи.

`src/` - основной исходный код Telegram-бота.

`tests/` - автотесты проекта.

`.env` - локальный файл с реальными секретами и переменными окружения. Не должен попадать в Git.

`.env.example` - пример переменных окружения для разработчиков. Показывает, какие значения нужно создать в `.env`.

`.gitignore` - правила Git: какие файлы не добавлять в репозиторий. Сейчас игнорирует `.env`, кэши Python, виртуальные окружения, логи, локальные базы, артефакты сборки и editor/OS-файлы.

`config.py` - текущая точка загрузки конфигурации из `.env`. Загружает переменные окружения через `python-dotenv` и предоставляет `API_KEY` как Python-переменную.

`docker-compose.yml` - заготовка для запуска нескольких сервисов проекта через Docker Compose: бот, база данных, Redis и другие зависимости.

`Makefile` - заготовка для коротких команд разработки: запуск, тесты, миграции, форматирование, сборка.

`pyproject.toml` - главный конфигурационный файл Python-проекта. Обычно хранит зависимости, настройки линтеров, форматтеров, pytest и metadata проекта.

`README.md` - входная документация проекта. Обычно содержит описание бота, инструкции запуска, переменные окружения и базовые команды.

`PROJECT_STRUCTURE.md` - этот документ. Описывает архитектуру папок и файлов проекта.

## Alembic

`alembic/alembic.ini` - конфигурация Alembic: путь к миграциям, параметры подключения к БД, настройки логирования миграций.

`alembic/env.py` - Python-точка входа Alembic. Подключает модели проекта и запускает миграции в online/offline-режиме.

`alembic/script.py.mako` - шаблон, по которому Alembic создает новые файлы миграций.

`alembic/versions/` - папка с конкретными миграциями БД.

`alembic/versions/.gitkeep` - пустой файл, чтобы Git хранил пустую папку `versions/`.

## Docker

`docker/Dockerfile` - инструкция сборки Docker-образа приложения: базовый Python-образ, установка зависимостей, копирование кода, команда запуска.

`docker/entrypoint.sh` - стартовый shell-скрипт контейнера. Обычно выполняет подготовку перед запуском: ожидание БД, миграции, запуск бота.

## Logs

`logs/.gitkeep` - фиксирует папку `logs/` в Git, пока реальные `.log`-файлы игнорируются.

## Scripts

`scripts/seed_db.py` - скрипт первичного наполнения базы данных тестовыми или стартовыми данными: товары, админы, настройки.

`scripts/set_webhook.py` - скрипт установки webhook для Telegram Bot API, если бот работает через webhook вместо polling.

## Source

`src/__init__.py` - делает `src` Python-пакетом.

`src/bot.py` - главная точка сборки Telegram-бота. Обычно здесь создаются Bot/Dispatcher, подключаются роутеры, middleware, конфиг и запускается polling или webhook.

## Source: callbacks

`src/callbacks/` - обработчики callback-query от inline-кнопок Telegram. Здесь живет логика реакций на нажатия кнопок.

`src/callbacks/__init__.py` - делает папку `callbacks` Python-пакетом и может экспортировать callback-роутеры.

`src/callbacks/catalog.py` - callback-логика каталога: открытие категорий, выбор товара, пагинация, действия с товаром.

`src/callbacks/navigation.py` - callback-логика навигации: назад, главное меню, переходы между экранами, переключение разделов.

## Source: core

`src/core/` - инфраструктурное ядро приложения: конфигурация, база данных, Redis, логирование.

`src/core/__init__.py` - делает `core` Python-пакетом.

`src/core/config.py` - правильное место для центральной конфигурации проекта. Сюда стоит перенести настройки из корневого `config.py`: токен бота, URL базы, Redis, API-ключи, режим окружения.

`src/core/database.py` - слой подключения к базе данных: engine/session, фабрика сессий, lifecycle подключения.

`src/core/logger.py` - настройка логирования: формат, уровень логов, вывод в консоль и/или файлы.

`src/core/redis.py` - подключение к Redis. Используется для кэша, rate-limit, FSM-состояний или временных данных.

## Source: handlers

`src/handlers/` - обработчики входящих Telegram-событий: команды, сообщения, ошибки, пользовательские и админские сценарии.

`src/handlers/__init__.py` - делает `handlers` Python-пакетом и может собирать/экспортировать роутеры.

`src/handlers/start.py` - обработчик команды `/start` и первичного входа пользователя в бота.

`src/handlers/errors.py` - централизованная обработка ошибок: логирование исключений, ответы пользователю, fallback-сценарии.

## Source: handlers/admin

`src/handlers/admin/` - сценарии администратора внутри Telegram-бота.

`src/handlers/admin/__init__.py` - делает `admin` Python-пакетом и может экспортировать admin-роутеры.

`src/handlers/admin/mailing.py` - админская рассылка сообщений пользователям.

`src/handlers/admin/panel.py` - главное меню или панель администратора.

`src/handlers/admin/statistics.py` - просмотр статистики: пользователи, платежи, активность, конверсии.

## Source: handlers/conversations

`src/handlers/conversations/` - многошаговые диалоги с пользователем. Обычно используют FSM-состояния.

`src/handlers/conversations/__init__.py` - делает `conversations` Python-пакетом.

`src/handlers/conversations/booking.py` - сценарий бронирования: выбор услуги/товара, даты, подтверждение.

`src/handlers/conversations/registration.py` - сценарий регистрации пользователя: сбор имени, контакта, подтверждений и сохранение в БД.

## Source: handlers/user

`src/handlers/user/` - пользовательские сценарии, не связанные с админкой.

`src/handlers/user/__init__.py` - делает `user` Python-пакетом и может экспортировать user-роутеры.

`src/handlers/user/catalog.py` - пользовательский просмотр каталога товаров или услуг.

`src/handlers/user/payments.py` - пользовательский сценарий оплаты: создание платежа, проверка статуса, подтверждение.

`src/handlers/user/profile.py` - профиль пользователя: личные данные, история, настройки, статус регистрации.

## Source: keyboards

`src/keyboards/` - генерация Telegram-клавиатур: reply-кнопки, inline-кнопки, меню админа и пользователя.

`src/keyboards/__init__.py` - делает `keyboards` Python-пакетом.

`src/keyboards/admin_kb.py` - клавиатуры для админ-панели.

`src/keyboards/inline_buttons.py` - общие inline-кнопки и фабрики callback-data.

`src/keyboards/main_menu.py` - основное меню пользователя.

## Source: middlewares

`src/middlewares/` - промежуточный слой обработки событий до handlers. Используется для логирования, доступа к БД, прав, throttling.

`src/middlewares/__init__.py` - делает `middlewares` Python-пакетом.

`src/middlewares/acl.py` - проверка прав доступа: админ/пользователь, разрешенные действия, ограничения.

`src/middlewares/database.py` - прокидывает DB-сессию в handlers, чтобы обработчики не создавали подключение вручную.

`src/middlewares/logging.py` - логирует входящие события, команды, ошибки и действия пользователей.

`src/middlewares/throttling.py` - защита от спама и слишком частых запросов.

## Source: models

`src/models/` - ORM-модели базы данных. Описывают таблицы и связи.

`src/models/__init__.py` - делает `models` Python-пакетом и может экспортировать все модели для Alembic.

`src/models/base.py` - базовый класс ORM-моделей и общие поля/metadata.

`src/models/payment.py` - модель платежа: сумма, статус, пользователь, провайдер, дата создания.

`src/models/product.py` - модель товара или услуги: название, цена, описание, доступность.

`src/models/user.py` - модель пользователя Telegram: telegram_id, имя, роль, регистрационные данные, timestamps.

## Source: repositories

`src/repositories/` - слой доступа к данным. Репозитории работают с БД и прячут SQL/ORM-детали от бизнес-логики.

`src/repositories/__init__.py` - делает `repositories` Python-пакетом.

`src/repositories/base.py` - базовый репозиторий с общими CRUD-операциями.

`src/repositories/payment_repo.py` - операции с платежами: создать, найти, обновить статус, получить историю.

`src/repositories/user_repo.py` - операции с пользователями: найти по telegram_id, создать, обновить профиль, проверить роль.

## Source: services

`src/services/` - бизнес-логика приложения. Сервисы связывают handlers, repositories, внешние API и правила системы.

`src/services/__init__.py` - делает `services` Python-пакетом.

`src/services/mailing_service.py` - логика рассылок: выбор аудитории, отправка сообщений, обработка ошибок доставки.

`src/services/payment_service.py` - бизнес-логика платежей: создание счета, проверка оплаты, обновление статусов.

`src/services/user_service.py` - бизнес-логика пользователей: регистрация, профиль, роли, проверки состояния пользователя.

## Source: utils

`src/utils/` - вспомогательные функции без собственного состояния и бизнес-слоя.

`src/utils/__init__.py` - делает `utils` Python-пакетом.

`src/utils/formatters.py` - форматирование текста для Telegram-сообщений: цены, даты, профили, карточки товаров.

`src/utils/scheduler.py` - планировщик фоновых задач: отложенные сообщения, периодические проверки, рассылки.

`src/utils/validators.py` - проверка пользовательского ввода: телефон, email, имя, даты, суммы.

## Tests

`tests/__init__.py` - делает `tests` Python-пакетом.

`tests/conftest.py` - общие pytest-фикстуры: тестовый бот, база, mock-сервисы, event loop.

`tests/test_registration.py` - тесты сценария регистрации пользователя.

`tests/test_start.py` - тесты команды `/start` и стартового поведения бота.

## Как части проекта соединяются

`src/bot.py` - собирает приложение: читает конфиг, создает bot/dispatcher, подключает handlers и middlewares.

`handlers` - принимают события Telegram и вызывают нужные `services`.

`services` - выполняют бизнес-логику и обращаются к `repositories`.

`repositories` - читают и пишут данные через `core/database.py`.

`models` - описывают структуру данных, с которой работают repositories и Alembic.

`keyboards` - отдают handlers готовые кнопки для пользовательского интерфейса в Telegram.

`callbacks` - обрабатывают нажатия inline-кнопок, которые были созданы в `keyboards`.

`middlewares` - добавляют общую обработку вокруг каждого события: логирование, DB-сессии, права, антиспам.

`core` - держит инфраструктуру: конфиг, БД, Redis, логирование.

`scripts` - выполняют отдельные технические задачи вне основного runtime бота.

`alembic` - синхронизирует структуру базы данных с ORM-моделями.

`tests` - проверяют, что сценарии бота работают после изменений.
